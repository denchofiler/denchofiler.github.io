ファイル名を付け始めて、最初に手が止まるのがここです。

1枚の請求書に、日付が3つも4つも載っています。

```
請求日        2026年1月15日
お支払期限    2026年2月28日
発行日        2026年1月16日
ご利用期間    2025年12月1日～12月31日
```

**どれを「取引年月日」として使えばいいのか。**

---

## 結論

> **原則として、その書類に記載された取引の年月日。請求書なら「請求日」、領収書なら「領収日」です。**

支払期限ではありません。自分が受け取った日でもありません。**書類の側に書かれている、その取引の日付**です。

迷ったときの判断基準はこれです。

**「相手がこの書類を発行した取引は、いつのものか」**

---

## 書類ごとの対応

| 書類 | 使う日付 | 補足 |
|---|---|---|
| 請求書 | **請求日** | 「発行日」表記のこともある。どちらか一方が載っていればそれを使う |
| 領収書 | **領収日** | 実際に代金を受領した日 |
| レシート | **発行日** | 印字されている日付 |
| 納品書 | **納品日** | |
| 注文書・契約書 | **注文日・契約日** | |
| クレジットカードのWeb明細 | **各利用日** | 明細全体の発行日ではなく、個々の取引の日付 |

---

## 使わない日付

### 支払期限

**最も間違えやすいのがこれです。**

「お支払期限 2026年2月28日」は、これから支払う予定の日であって、取引が行われた日ではありません。

金額の隣に大きく書かれていることが多く、目に入りやすいので注意してください。

### 自分がメールを受け取った日

受領日は取引年月日ではありません。

月末に発行された請求書が翌月1日に届くことはよくありますが、**取引年月日は書類に記載された日付のまま**です。受け取った側の都合で日付は変わりません。

### ファイルの作成日・更新日

PCが記録している日付は無関係です。ファイルをコピーしただけで変わってしまうため、そもそも根拠になりません。

### 会計処理をした日

仕訳を切った日、入力した日も取引年月日ではありません。

---

## 判断に迷う場面

### 請求日と発行日が両方ある

どちらでも構いません。**社内で「請求日を使う」と決めて統一してください。**

重要なのは、**同じルールで一貫して付けること**です。書類ごとにバラバラだと、後から探せなくなります。

### 日付の記載が一切ない

まれにあります。この場合は、

1. メール本文や送付状に日付があればそれを使う
2. 何もなければ、受領日を使う

いずれの場合も、**なぜその日付にしたのかを事務処理規程または運用ルールに書いておいてください。**判断の根拠が残っていることが重要です。

### 期間が書かれている（サブスクリプションなど）

「ご利用期間 2025年12月1日～12月31日」のような表記の場合、**請求日を使います。**期間の開始日や終了日ではありません。

### 月をまたぐ場合

12月分の役務提供に対して1月に請求書が発行された場合、取引年月日は**1月の請求日**です。

会計上の計上月（12月）とはズレますが、**電帳法の検索要件は書類の日付で判断します。**ここは会計処理と別に考えてください。

---

## 書式はどうするか

法令で形式は定められていません。ただし、実務上は **`YYYYMMDD`（8桁）** を強く推奨します。

```
20260115_1234567_テスト工業株式会社.pdf
```

理由は3つあります。

1. **名前順に並べると日付順になる。**`2026-1-15` や `R8.1.15` だとバラバラに並びます
2. **区切り文字を使わないので、ファイル名が短くなる**
3. **Excelでの並べ替え・突き合わせがしやすい**

和暦（令和8年1月15日）で書かれた請求書も、**ファイル名は西暦8桁に統一してください。**元号をまたぐと並び順が壊れます。

---

## 取引年月日を間違えると、何が問題になるのか

検索要件は「取引年月日・取引金額・取引先で検索できること」です。

支払期限をファイル名に入れてしまうと、税務調査で「2026年1月の取引を見せてください」と言われたときに、**その書類が出てきません。**1月の取引なのに、ファイル名が2月になっているためです。

件数が少ないうちは目視で探せますが、数百件になると破綻します。

**最初にルールを決めておくことが、後の作業量を決めます。**

---

## まとめ

- 取引年月日は、**書類に記載された取引の日付**。請求書なら請求日、領収書なら領収日
- **支払期限は使わない。**最も間違えやすい
- **受領日・ファイル作成日・仕訳日も使わない**
- 請求日と発行日の両方があるなら、**どちらかに統一する**
- 月をまたぐ場合は**請求日**。会計上の計上月とは別に考える
- 書式は **`YYYYMMDD` の8桁**。和暦も西暦に直す
- 迷った場合の判断は、**なぜそうしたかを運用ルールに残しておく**

## 日付の取り違えを自動で防ぐ

ここが厄介なのは、**1枚のPDFに日付が複数あること**です。目視で1件ずつ確認していると、必ずどこかで取り違えます。

請求書・領収書のPDFを読み込ませると、取引年月日を自動で判定してファイル名の案を作るツールを公開しています。

**このツールは、請求日と支払期限を区別します。**

判定に自信がない場合は、候補を根拠付きで並べます。

```
20260115（請求日）    20260228（支払期限）
```

**なぜその日付を選んだのかが見える状態**で、違っていればクリックひとつで直せます。全部お任せにせず、最終確認は人が行う前提で作っています。

和暦（令和8年1月15日）や全角数字にも対応していて、**すべて西暦8桁に揃えて出力します。**

**索引簿CSVの作成までは無料で、件数制限もありません。**読み込んだファイルは**外部に送信されません**。すべてブラウザの中だけで処理します。
